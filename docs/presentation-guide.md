# README 작성 기준

이 문서는 같은 작성자가 관리하는 스킬 저장소의 소개 형식을 맞추기 위한 기준입니다.
스킬의 기능, 호스트, 설치 단위, 라이선스까지 같다는 뜻은 아닙니다.

## 기본 구조

README는 다음 순서로 작성합니다.

1. 제품 이름, 한 문장 소개, 버전·호스트·라이선스, 필요한 성숙도 안내
2. `소개`: 해결하는 문제와 적용 범위
3. `설치`: 요구 환경, 실제 설치 단위, 복사 가능한 설치 방법
4. `사용법`: 첫 요청과 예상 결과
5. `예시`: 확인 가능한 예제나 명확히 표시한 합성 사례
6. `구성`: 설치 파일과 개발·평가 자료의 구분
7. `검증`: 실행 명령, 검사 범위, 검증하지 않은 항목
8. `제한 사항과 개인정보`: 지원 범위, 권한, 자료 취급 주의사항
9. `문서`: 상세 사용법과 유지보수 문서 링크
10. `라이선스`: 실제 LICENSE의 상태와 일치하는 안내

상단에는 설치·사용법·예시·검증으로 이동하는 링크를 둡니다. 본문은 한국어를 기본으로
하고, 제품명·명령·코드 식별자는 원문을 유지합니다. 기존 영문 상세 문서는 필요에 따라
유지할 수 있습니다.

## 표기와 분량

- 제목은 제품 이름만 씁니다. 호스트와 버전은 별도 상태 줄에 표시합니다.
- 버전은 `vX.Y.Z` 형식으로 표시하고 실제 배포 메타데이터와 맞춥니다.
- 설치 단위와 호환 호스트는 각 저장소의 실제 구조를 설명합니다. 겉모양을 맞추려고
  경로나 실행 방식을 바꾸지 않습니다.
- README에는 첫 사용에 필요한 내용과 중요한 제한을 남깁니다. 긴 설정표, 추가 예제,
  평가 절차는 `docs/`의 목적별 문서로 연결합니다.
- 스크린샷과 영상은 기능을 설명하는 실제 예제일 때 사용합니다. 장식용 배지나
  측정하지 않은 성능·효과 주장은 추가하지 않습니다.
- 합성 예시, 과거 평가 기록의 재실행, 실제 모델·사용자 평가는 구분합니다.
- 라이선스, 공개 여부, 릴리스 게시 여부는 실제 확인된 상태를 따릅니다. 문서 정비만으로
  이용 허락이나 배포 완료를 주장하지 않습니다.

## 변경 후 확인

- 수정한 Markdown의 상대 링크와 제목 앵커가 실제 대상으로 연결되는지 확인합니다.
- 명령이 실행되는 위치, 필요한 의존성, 생성되는 파일을 확인합니다.
- 패키지 파일 목록이 있는 저장소는 새 문서를 목록에도 추가합니다.
- 저장소의 검증 명령을 실행하고, 실행하지 못한 검사는 통과로 표현하지 않습니다.
- 문서만 바꾼 경우 스킬 지침·실행 스크립트·평가 원본이 바뀌지 않았는지 비교합니다.
