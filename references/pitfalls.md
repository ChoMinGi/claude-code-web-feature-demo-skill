# 재생할 때 확인할 사항

## 창 크기

본 재생은 Chrome 창을 최대화하고 페이지가 창 크기를 따르게 한다. 다른 모니터에서 보려면 창을 직접 옮긴다.

## 이전 데모와 데이터 정리

새 데모를 시작하기 전에 앞 데모 창을 닫고 정리가 끝났는지 확인한다. `SIGINT`·`SIGTERM` 종료에는 정리를 시도하지만 `SIGKILL`이나 프로세스 충돌에는 실행되지 않을 수 있다. 이 경우 남은 데이터를 따로 확인한다.

## 재생 시작 확인

본 재생을 백그라운드에서 실행한 뒤 첫 장면이 표시됐는지 확인한다. 고정 시간만 기다리고 재생이 시작됐다고 가정하지 않는다.

## 장면 확인

`seen()`은 요소가 보이지 않으면 실패를 기록하고 실행을 중단한다. 로그인 화면의 제목처럼 다른 장면에서도 보일 수 있는 넓은 셀렉터 대신, 해당 장면의 결과를 확인할 수 있는 요소를 고른다.

## 로컬 연결 제한

브라우저의 외부 HTTP(S)·WebSocket 요청은 차단된다. 외부 CDN이나 원격 인증 서버가 필요한 화면은 그대로 시연할 수 없다. 서비스의 서버 측 요청은 차단 대상이 아니므로 백엔드 설정을 별도로 확인한다. 서비스 워커는 요청 차단을 우회하지 않도록 비활성화된다.

## 재생 중 소스 수정

개발 서버의 자동 새로 고침이 장면을 끊을 수 있다. 재생 중에는 소스를 수정하지 않는다.

## 서버 오류 주입

조회 요청은 화면 코드가 재시도할 수 있다. 한 번만 실패시키면 오류 화면이 보이지 않을 수 있으므로 조회 오류를 보여 줄 때는 `inject()`의 `on` 상태를 유지하고 재시도 장면 전에 끈다. 저장 요청처럼 재시도가 없는 경우에는 `times`를 쓸 수 있다.

## 오프라인과 요청 가로채기

`context.setOffline(true)`는 브라우저 요청을 끊지만, 가로채기 안의 `route.fetch()` 요청에는 적용되지 않는다. 오프라인 장면에서는 해당 요청을 가로채지 않는다.

## 바뀌는 화면 이름

동작 뒤 대화상자 제목이 바뀌면 이름으로 찾던 로케이터가 더는 맞지 않는다. 바뀐 뒤에는 현재 화면의 이름이나 역할로 다시 찾는다.

## 화면에서 만든 데이터

화면의 만들기 버튼으로 생성한 데이터는 어댑터의 생성 함수를 거치지 않는다. 주소나 응답에서 ID를 확인해 정리 대상에 추가한다.

## Playwright가 없는 서비스

`install.sh`를 폴더 인자 없이 실행하면 `~/.cache/web-feature-demo/runner`에 `playwright-core`를 설치한다. 처음에는 인터넷 연결이 필요하다. 브라우저는 설치된 Chrome을 사용한다.

## 녹화

`RECORD=1`로 설치와 재생을 실행하면 브라우저 화면을 WebM으로 저장한다. `DEMO_LOGIN_MODE=show`에서는 로그인 화면부터 녹화하고, `before`에서는 로그인 뒤 첫 장면부터 녹화한다. 마지막 장면 뒤에 녹화를 멈춘다. Chrome 창은 계속 열어 둔다.

녹화할 때는 1280×720 화면 크기를 쓴다. `DRY=1` 점검에도 `RECORD=1`을 주면 같은 크기로 확인할 수 있다. 처음 녹화할 때는 Playwright용 FFmpeg 설치가 필요하다. 기존 서비스의 Playwright가 녹화 API를 지원하지 않으면 스킬 폴더의 `scripts/install.sh`을 앱 폴더 인자 없이 실행해 독립 실행기를 사용한다.
