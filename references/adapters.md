# 서비스별 어댑터

일반적인 이메일·비밀번호 로그인은 `scripts/adapters/generic.mjs`로 처리한다.

| 환경 변수 | 용도 |
|---|---|
| `DEMO_URL` | 데모할 로컬 화면 주소. 필수 |
| `DEMO_LOGIN_URL` | 로그인 화면 주소. 생략하면 `DEMO_URL` 사용 |
| `DEMO_USER`, `DEMO_PASSWORD` | 둘 다 있으면 로그인 폼 입력 |
| `DEMO_LOGIN_MODE` | `none`: 로그인 생략, `before`: 시연 전 로그인, `show`: 로그인 장면 포함 |
| `DEMO_API` | 로컬 API 주소. 생략하면 `DEMO_URL`의 출처 사용 |
| `DEMO_TOKEN` | API에 붙일 Bearer 토큰. 쿠키 로그인에는 불필요 |

모드를 생략하면 계정 정보가 있을 때 `before`, 없을 때 `none`으로 동작한다. `before`와 `show`는 계정 정보 두 값이 모두 필요하다. `show`는 로그인 페이지에서 녹화를 시작하므로 입력 과정이 영상에 포함된다. 로그인 후 URL이 바뀌거나 비밀번호 입력란이 화면에서 제거돼야 완료로 판단한다. 데모 데이터는 `api(page, "POST", …)`로 만들고 `cleanup(() => api(page, "DELETE", …))`로 정리할 수 있다.

`generic.api()`는 로컬 API 주소만 허용하고 리다이렉트를 따라가지 않으며, 성공 범위 밖의 응답은 오류로 처리한다. 정리용 요청 세션은 재생 직후 쿠키를 복사해 준비하므로 창을 닫은 뒤에도 `generic.api()`로 데이터를 지울 수 있다. 별도 어댑터를 쓴다면 `assertLocalUrl()`로 요청 주소를 검증하고 `requestForApi(page)`로 요청한다. 정리 API의 응답 상태도 확인한다.

SSO, 2단계 인증, 다른 형태의 로그인 폼, 복잡한 데이터 생성 절차에는 서비스별 어댑터를 만든다. `scripts/adapters/<서비스>.mjs`에 필요한 로그인, 데이터 생성, 정리 함수만 넣는다. 원격 인증 페이지가 필요한 흐름은 로컬 연결 제한 때문에 이 스킬로 재생할 수 없다. 주소와 계정 정보는 환경 변수로 받고 파일에 비밀번호나 토큰을 적지 않는다.

데모 데이터는 끝날 때 삭제할 수 있도록 생성 직후 정리 작업을 등록한다. 화면에서 생성한 데이터도 ID를 추적해 정리한다. 강제 종료 후 찾을 수 있도록 데모 데이터 이름에 구분 가능한 접두를 붙이는 편이 좋다.

셀렉터는 가능하면 `getByRole`, `getByText`, `aria-label`처럼 화면에 드러난 정보로 찾는다. 기존 화면 테스트가 있다면 셀렉터를 참고한다. 서비스마다 다른 화면 경로와 셀렉터는 별도 문서에 기록한다.

처음에는 `scripts/examples/template.mjs`를 복사해 한 장면으로 실행한다. 로그인과 데이터 생성이 필요할 때만 어댑터를 늘린다.
