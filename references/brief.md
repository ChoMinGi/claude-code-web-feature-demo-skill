# 데모 내용 정하기

「로컬에서 보여줘」처럼 대상이 짧게 언급되면 대화 맥락과 변경 내용을 확인한다. 최근에 고친 작은 결함과 기능 전체가 함께 있을 수 있으므로 무엇을 먼저 보여 줄지 정한다.

대화 내용, 브랜치와 커밋, `git diff --stat`, 화면 경로를 참고한다. 저장소가 없으면 사용자가 알려 준 기능과 실행 중인 화면을 기준으로 한다.

| 항목 | 정할 내용 |
|---|---|
| 대상 | 기능이나 수정 내용 중 이번에 보여 줄 것 |
| 보는 사람 | 설명 수준을 맞출 대상 |
| 장면 | 사용자가 실제로 겪는 순서 |
| 전후 비교 | 수정 전 화면을 확인해 띄울 수 있는지 |
| 실패 상황 | 서버 오류나 오프라인이 시연 대상인지 |
| 길이 | 장면 수와 설명을 보여 줄 시간 |
| 영상 | Chrome 시연만 할지, WebM도 저장할지 |
| 로그인 | 필요 없는지, 시연 전에 할지, 로그인 과정도 보여 줄지 |

대상이 하나로 좁혀지면 장면 순서, 예상 길이, 선택한 옵션을 3~5줄로 먼저 보여 주고 진행한다. 대상이나 옵션이 맥락으로 정해지지 않으면 빠진 항목만 한 번에 묻는다.

## 설명 문구

- 설명은 한국어로 쓴다. `say()`는 한글이 없으면 경고를 남긴다.
- 한 장면에는 단계, 제목 한 줄, 설명 0~3줄을 쓴다.
- 제목에는 화면에서 일어나는 일을 쓴다. 화면 문구는 「」로 그대로 인용한다.
- 파일 이름, 함수 이름, 검증 번호처럼 시청자에게 필요 없는 정보는 넣지 않는다.
- 화면 문구가 기능을 암시해도 실제로 확인한 동작만 설명한다. 수정 전 동작도 직접 띄워 확인했거나 기록이 있어야 한다.
